# О проекте
Что это за система, для кого она и какую бизнес-задачу решает. 2 или 3 предложения.

# Архитектура
Основные модули и за что они отвечают. Как они связаны. Где точки входа.

# Договорённости
Принятые и запрещённые библиотеки. Формат логов. Обработка ошибок.
Правила именования и список того, что считается публичным интерфейсом и не меняется без согласования.

# Как проверять
Команда для запуска тестов. Команда для линтера. Что должно проходить до пул-реквеста.

# Чего не делать
Модули, которые нельзя трогать. Операции, для которых нужно подтверждение человека.
Данные, которые нельзя использовать в примерах.

# Типичные задачи
2 или 3 примера того, как здесь принято делать типовые вещи, со ссылками на образцовый код.

# Порог спецификации
Для каких изменений сначала пишется спецификация в specs/. Например: новый публичный интерфейс,
изменение схемы данных, всё, что затрагивает больше 1 модуля.

# Работа с ИИ в этом репозитории
- Правила использования ИИ: docs/ai/policy.md. Что нельзя отправлять в модель, написано там.
- Спецификации лежат в specs/, шаблон: specs/_template.md.
- В каждом пул-реквесте отмечается участие ИИ (шаблон в .github/pull_request_template.md).
- Действия на проде, удаление данных и внешняя отправка данных требуют подтверждения человека.
